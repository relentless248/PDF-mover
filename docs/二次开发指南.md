# 二次开发指南

> 本文面向需要修改、扩展本工具的开发者。日常使用请看[《操作手册》](../操作手册.md)，本文只讲实现。
> 程序内「❓ 帮助」的文本在 `core/help_text.py`，随程序分发。

## 0. 环境与运行

- **仅支持 Windows**：tkinter 界面、`os.startfile`、批处理脚本、Tesseract / Poppler 均为 Windows 版本。
- 嵌入式运行时：`python/python.exe`（3.13）；依赖见 `requirements.txt`（只声明最低版本，代码使用 `Image.Resampling` 等要求 Pillow ≥ 9.1）。
- 运行测试（不依赖界面 / OCR，约 0.3 秒）：

  ```bash
  python -m unittest discover -s tests -v
  ```

- 运行日志：根目录 `run.log`（logging，2MB 滚动备份×2），排障第一入口。

## 1. 模块地图

| 文件 | 职责 | 依赖 GUI |
|------|------|----------|
| `pdf_mover.py` | 主程序：界面 + 流程编排（`PDFMoverApp`） | 是 |
| `core/settings.py` | 配置单例：默认值、深合并、派生正则、段式↔正则互转 | 否 |
| `core/matching.py` | 纯逻辑：年份提取、文件夹匹配、路径防碰撞 | 否 |
| `core/settings_dialog.py` | 可视化设置面板（四页签） | 是 |
| `core/help_text.py` | 程序内帮助文本 | 否 |
| `YearArchiver/year_archiver.py` | 独立小工具（未找到项目按年份归档） | 是 |
| `tests/test_core_logic.py` | 纯逻辑单元测试 | 否 |

依赖方向：`pdf_mover → core.*`、`YearArchiver → core.*`；`core` 内部不反向依赖业务代码。
`core/matching.py` 不读全局配置、不碰文件系统（存在性检查可注入），这是它可单测的前提——**新的纯逻辑请放这里**。

## 2. 线程模型（改前必读）

- **只有主线程能碰 Tk 控件与界面状态**。工作线程一律通过 `self.root.after(0, callback)` 回主线程。
- 三条后台线程：
  1. **OCR 线程** `process_pdf_thread`：渲染 + OCR，完成后 `after` 回 `on_ocr_done`，并把已渲染的首页图片一并传回（识别与预览共用同一次渲染，勿再二次渲染）；
  2. **索引线程** `build_folder_index_thread`：扫描文件夹，进度经 `after` 更新；
  3. **`run_with_timeout` 的守护线程**：包装单次阻塞调用（OCR / 渲染），超时抛 `TimeoutError`。
- 共享状态：`all_project_folders` 由 `thread_lock` 保护；`ocr_cache` / `search_cache` 目前只在主线程读写（`_do_search_folders` 经 `after` 回主线程执行）——新增线程写入前先想清楚归属。
- **已知限制**：`run_with_timeout` 超时后 daemon 线程无法被强杀（Python 线程的固有限制），卡死的 poppler / tesseract 子进程会继续持有句柄。彻底解决需要把子进程改为可主动 `terminate()` 的独立方案，目前未做。

## 3. 自动运行状态机（全项目最容易改坏的地方）

状态位：`auto_run`（自动模式总开关）、`auto_run_paused`（暂停）、`processing`（OCR 忙）、`current_index`、`pause_dialog`。

主循环：

```
start_auto_run → auto_run_next（取下一个文件）→ on_select_pdf
  → OCR 线程 → on_ocr_done → _apply_ocr_results → search_folders
  → _do_search_folders → auto_check_and_process（决策树）→ 各 auto_* 处理函数
  → handle_auto_run_after_action(removed) → auto_run_next
```

`auto_check_and_process` 决策优先级：自动旋转重试 → “未找到项目”文件再归档 → 无编号 → 无匹配文件夹 → 多匹配 → 多 Test Data → see 关联 → 归档/复制。

**暂停对话框约定**（历史上两次事故都在这里）：

- `AutoPauseDialog` 是**唯一计时源**（内部倒计时）。不要再外挂 `root.after` 定时器做同样的事——两套计时必然双重触发。
- `show_pause_dialog` 的回调必须在创建时用默认参数捕获当时的路径：`lambda p=self.current_pdf: ...`。否则 20 秒后定时器触发时 `current_pdf` 可能已被用户切走，**会错误操作另一个文件**（晚绑定）。
- 对话框回调保证整个生命周期最多触发一次；对话框被外部销毁（`close_pause_dialog`，如「停止自动」）时倒计时自动失效，不触发回调。
- `button_guard` 装饰器：进入手动操作前取消挂起定时器、防止重入；**所有会动文件的手动按钮都应挂它**。

## 4. 配置体系

链路：

```
DEFAULT_SETTINGS (core/settings.py)
  → load_raw_settings() 读 settings.json
  → deep_merge 深合并（用户配置只覆盖出现的键，缺项回退默认值）
  → Settings 单例 → _recompile() 从 project_pattern 派生全部正则
     （project_regex / see_regex / analyze_see_pattern / analyze_no_see_pattern / see_from_filename_regex）
```

- 所有编号相关正则都由 `project_pattern` 单点派生，**不要在业务代码里另写业务正则**；新增编号相关逻辑优先复用 `settings.project_regex`。
- **新增配置项三步**（缺一不可）：
  1. `DEFAULT_SETTINGS` 加默认值——必须，保证老 `settings.json` 缺项时行为不变；
  2. `Settings` 加 property（或直接读 `data[...]`）；
  3. `core/settings_dialog.py` 加控件，并在 `_save()` 写回 `data`。
- 若涉及 OCR 数值参数的界面提示，同步更新 `OCR_HINTS` / `OCR_FIELDS`。
- 热更新：设置保存后 `open_settings()` 会依次 `reload_settings()` → `reload_derived()`（模块级正则）→ `_apply_derived_regexes()`（实例级）→ `_apply_runtime_ocr()`。新配置项若被线程或长期缓存持有，需要在这里补刷新逻辑。
- **文件名模板与解析正则必须成对修改**：`build_filename` 生成、`analyze_*` 解析。二者分隔符不一致会导致工具认不出自己重命名的文件（真实发生过的 bug，`tests` 里有回归用例 `test_generated_filenames_are_parseable`）。

## 5. 文件操作规范（动用户文件，务必谨慎）

- 移动 / 复制 / 重命名一律走 `perform_file_operation` / `rename_with_retry`（内置占用重试），**不要**直接 `shutil.move` / `os.rename`。
- 任何目标路径先过 `is_target_path_valid`（`normcase` 白名单校验），防止越权写入。
- 防碰撞：`core.matching.unique_path` / `unique_target_path`，不要手写 `while os.path.exists` 循环。
- 配置 / Excel 写入用 `atomic_write_json` / `atomic_write_excel`（临时文件 + `os.replace` 原子替换）。
- 编号 → 文件夹查找统一走 `_find_folders_for_id`（内置 LRU 缓存），不要绕开缓存自写扫描。

## 6. 日志与错误处理

- 用模块级 `log`（`logging.getLogger('pdf_mover')`），**不要 `print`**。
- 级别约定：`DEBUG` 调试细节（默认不落盘）、`INFO` 正常流程、`WARNING` 可恢复异常 / 重试、`ERROR` 失败（带 `traceback.format_exc()`）。
- 用户需要知晓的错误同时用 `messagebox` 告知；日志负责留痕回溯。
- 收紧异常捕获：只清理资源的场景用 `except OSError` / `except Exception`，不要裸 `except:`。

## 7. 测试

- 纯逻辑放 `core/matching.py`（不读全局配置、不碰文件系统 / 界面），这是可测性的前提。
- 运行：`python -m unittest discover -s tests -v`；提交前务必全绿。
- 加测试：`tests/test_core_logic.py` 按现有测试类分组；改 pure 函数或派生正则时**先补用例再改实现**。
- 主程序中仅依赖少量实例状态的方法，可用 `PDFMoverApp.__new__` 构造桩对象直接测（见 `TestAppPathValidation`），无需启动界面。

## 8. 文档维护纪律

文档按受众各留一份权威版本，README 只做导流、不重复内容：

| 受众 | 权威文档 |
|------|----------|
| 使用者（无需编程） | [操作手册.md](../操作手册.md) |
| 开发者 | 本文 |
| 程序内帮助 | `core/help_text.py` |

- 改了行为必须同步改对应文档：设置页签 / 参数默认值变更 → 操作手册第十一章 + `help_text.py`；新增纯函数 / 线程 / 状态位 / 配置项 → 本文。
- 隐私红线：任何文档、示例、测试中不得出现真实盘符路径、内网目录结构、真实编号规则前缀——一律使用虚构示例（如 `D:/项目档案/2026年`、`(?:AB|CD)\d{10}`）。
- 依赖升级：`requirements.txt` 只声明最低版本；升级后跑一遍测试并用真实文件做一轮回归。
